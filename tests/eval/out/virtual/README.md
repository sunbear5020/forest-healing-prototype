> 엔진 추천을 "전문가 검증"으로 표현하는 근거로 쓸 수 없습니다. 판정 절차를 미리 시험하고 엔진의 약점을 찾는 용도입니다.

## 방법
- 사례: `tests/eval/out/expert_cases.csv` 100건(자해 있음 10건). 목록 A·B 중 하나가 엔진 상위 3곳, 다른 하나는 같은 제외 규칙을 거친 **가까운 순 3곳**(기준선). 순서는 무작위.
- 판정자: 서로 독립된 하위 에이전트 2개. 판정자 1은 산림치유지도사 관점(Claude Sonnet 계열), 판정자 2는 정신건강임상심리사 관점(Claude Haiku 계열). 엔진을 만든 세션과 다른 모델 크기이며 같은 회사 모델.
- 판정자가 읽은 파일: 판정 지침(`INSTRUCTIONS.md`)과 사례 CSV뿐. 저장소·정답표·엔진 출력·서로의 판정은 보지 않도록 지시. 웹 검색 금지.
  지시를 지켰는지는 하위 에이전트 보고에 의존합니다(확실하지 않음).
- 계산: `python tests/eval/kappa.py answer_key.csv rater1.csv rater2.csv` → `kappa_output.txt`

## 해석
1. **실제 약점으로 보이는 것: 미세먼지·비 날씨에 실외형 시설을 1순위로 올림.** 호흡기 가중치가 0.25 미만이면 PM2.5 나쁨은 환경 점수 감점(−10)뿐이라, 효과 점수가 높은 실외형 시설이 실내 시설 있는 곳을 앞섭니다. 두 판정자 모두 PM2.5 나쁨 26건 중 24건에서 기준선을 골랐고 메모 이유가 같습니다("PM 나쁨인데 1순위 야외형"). 엔진 수정 후보입니다.
2. **판정 설계의 편향**: 판정자는 시설 이름·이동시간·실내 표시만 봤고, 엔진이 쓰는 효과 근거(설문 효과모형)나 수관 피복 등은 보지 못했습니다. 이 정보만으로는 가까운 순 목록이 구조적으로 유리합니다. 맑은 날 결과(판정자 2: 기준선 24건)는 이 편향이 크게 작용했을 가능성이 있습니다(추측입니다).
3. 그럼에도 두 판정자가 우열을 가린 129회 중 엔진을 고른 것이 1회라는 점은, **엔진의 개인화 근거가 사용자에게 보이지 않거나 설득력이 없다**는 신호로 받아들입니다. 실제 전문가 판정 때는 사례표에 엔진의 추천 이유를 넣을지(넣으면 블라인드가 깨짐) 사전에 정해야 합니다.

4. 판정자 2가 '아니오'로 본 1건(C064: 자해 생각 있음, 강풍)은 안전 안내가 '숲·공원 대안'을 함께 권하는데 강풍 상황과 맞지 않는다는 지적입니다. 대체 경로 안내에 기상 위험을 반영하지 않는 것은 실제 결함입니다.
